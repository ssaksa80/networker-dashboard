## Verdict

The code is healthy at the level CI measures:
- Lint is clean.
- All 122 unittest tests pass on the production runtime (embedded CPython
  3.12.10), 3.13 and 3.14.
- Security headers, CSRF, cookie flags and output escaping all behave
  correctly live.
- No XSS was found.

It is weaker where nothing measures it: the collectors, the scheduled-report
pipeline, the session lifecycle and the installer. The review found
**13 High-severity issues**, among them:
- two ways to exfiltrate stored credentials (S1, S2);
- an unauthenticated one-socket denial of service (S3);
- counting bugs that make report numbers wrong under ordinary conditions
  (C1–C3, C10, C12);
- an upgrade path that can leave the service stopped (O1).

None of these were within what the July report card assessed, so the grades
below are lower.

## Strengths worth keeping

- **Profile→destination credential binding** and AAD-bound encryption: a
  ciphertext only decrypts in its own slot. S2 is a gap in the save path that
  feeds the guard, not in the guard itself.
- **Key management fails closed.** An unreadable key is refused, never
  silently regenerated.
- **Complete CSRF coverage when auth is on:** one gate and an explicit POST
  allow-list; every comparison uses `hmac.compare_digest`.
- **No generic static-file route.** Token and date inputs are regex-pinned,
  so there's no traversal surface.
- **Consistent output escaping** in `app.js`, `tv.js` and all email HTML. No
  inline event handlers and no CDNs.
- **Supply chain:** SHA-pinned CPython and NSSM, and a bundle allow-list that
  fails on drift in either direction.
- The deploy scripts encode hard-won field lessons: NSSM UTF-16 decoding, a
  STOP_PENDING guard, a pinned-bind-only port-owner kill, and a consecutive-probe
  health gate.
- Structured JSON logs with request ids and CR/LF scrubbing.
